# Подпись и публикация

Firefox (релиз, Beta, Android) ставит только подписанные расширения. Подписывает Mozilla через addons.mozilla.org (AMO). Есть два пути: подпись для самостоятельного распространения (файл `.xpi` раздаёте сами, например через GitHub Releases) и публикация в каталоге AMO.

## 0. Подготовка

1. Создайте аккаунт на https://addons.mozilla.org (через Firefox Account).
2. Установите Node.js 18+ и выполните `npm install` в корне проекта.
3. Проверьте расширение: `npm run lint`. Исправьте ошибки, предупреждения прочитайте.
4. Версия в `src/manifest.json` — три числа через точки (`2.0.0`). Каждая загрузка на AMO должна иметь новую, ещё не использованную версию.

## 1. Подпись для самостоятельного распространения

### Вариант A: через сайт

1. https://addons.mozilla.org/developers/ → **Submit a New Add-on**.
2. Выберите **On your own** (самостоятельное распространение).
3. Загрузите `.xpi` (`npm run build` кладёт архив в `dist/`).
4. На вопрос об исходном коде ответьте «нет»: код не минифицирован, сборки нет.
5. После проверки скачайте подписанный `.xpi` из раздела **Manage Status & Versions**.

### Вариант B: командой

1. Получите ключи: https://addons.mozilla.org/developers/addon/api/key/ → **Generate new credentials**. Вы получите `JWT issuer` (ключ) и `JWT secret`. Храните их в секрете и никогда не коммитьте.
2. Подпишите:

```bash
npx web-ext sign --source-dir src --artifacts-dir dist --channel unlisted \
  --api-key "ВАШ_JWT_ISSUER" --api-secret "ВАШ_JWT_SECRET"
```

Подписанный файл появится в `dist/`. Его можно ставить в обычный Firefox. Все версии, даже неопубликованные, остаются в вашем кабинете на AMO.

## 2. Публикация в каталоге AMO

1. https://addons.mozilla.org/developers/ → **Submit a New Add-on** → **On this site** (в каталоге).
2. Загрузите `.xpi`. Валидатор проверит манифест. В манифесте уже заданы `id`, `strict_min_version` и `data_collection_permissions`, без них новые расширения не принимаются.
3. Заполните карточку:
   - название, краткое описание (summary) и подробное описание;
   - категория (например, **Tabs** или **Appearance**);
   - иконка и 2–5 скриншотов (вкладка в тёмной и светлой теме, режим правки, настройки);
   - лицензия: MIT;
   - политика конфиденциальности: вставьте раздел «Конфиденциальность» из README.
4. Отправьте на проверку. Проверяют вручную; пока идёт проверка, расширение не видно в каталоге. Если запросят правки, исправьте, поднимите версию и загрузите заново.

Что проверяющие смотрят в этом расширении:

- **Разрешение `bookmarks`** необязательное и запрашивается по кнопке. В описании объясните, зачем оно: сайты с панели закладок показываются плитками.
- **Данные наружу.** В манифесте заявлены `browsingActivity` (домены плиток уходят в сервис значков Google) и `locationInfo` (введённый город уходит в Open-Meteo). Это нужно описать и в политике конфиденциальности. Если уберёте погоду или внешние значки, уберите и соответствующую запись в `data_collection_permissions`; если внешних запросов не останется совсем, укажите `"required": ["none"]`.
- **Идентификатор** `tablo-newtab@btwkek` менять после первой публикации нельзя: по нему Firefox связывает версии и данные пользователей.

## 3. GitHub

### Репозиторий

1. Создайте на GitHub пустой репозиторий `tablo-newtab` (без README и лицензии) — имя должно совпадать со ссылкой в `manifest.json` и `package.json`, иначе поправьте их.
2. В папке проекта:

```bash
git init -b main
git add .
git commit -m "Первая версия"
git remote add origin https://github.com/Btwkek/tablo-newtab.git
git push -u origin main
```

3. В карточке репозитория (**About**) добавьте описание и темы: `firefox-extension`, `new-tab`, `webextension`.

В репозиторий идёт только исходный код. Файлы `.xpi`, `dist/`, `node_modules/` и ключи в `.gitignore` и не коммитятся.

### Быстрый релиз (с готовым workflow)

Один раз: создайте секреты `AMO_API_KEY` и `AMO_API_SECRET` (см. «Релиз автоматически» ниже). Дальше для каждого релиза:

```bash
# 1. поднять версию в src/manifest.json и package.json, дописать CHANGELOG.md
git add .
git commit -m "Release 2.1.0"
git push

# 2. тег должен совпадать с версией в манифесте: v + версия
git tag v2.1.0
git push origin v2.1.0
```

GitHub Actions проверит версию, запустит lint, подпишет `.xpi` в Mozilla и прикрепит его к релизу. Ход сборки: вкладка **Actions** в репозитории.

### Релиз вручную

1. Поднимите версию в `src/manifest.json` и `package.json`, допишите `CHANGELOG.md`, закоммитьте.
2. Подпишите расширение (раздел 1) и получите `.xpi`.
3. Поставьте тег и отправьте его:

```bash
git tag v2.0.0
git push origin v2.0.0
```

4. На GitHub: **Releases** → **Draft a new release** → выберите тег `v2.0.0`, заголовок «2.0.0», в описание вставьте раздел из `CHANGELOG.md`.
5. Перетащите **подписанный** `.xpi` в блок **Attach binaries** и нажмите **Publish release**.

Пользователи открывают ссылку на `.xpi` из релиза в Firefox и нажимают «Добавить». Назовите файл без пробелов, например `tablo-newtab-2.0.0.xpi`.

### Релиз автоматически (по желанию)

В проекте есть `.github/workflows/release.yml`: при пуше тега он проверяет версию, запускает lint, подписывает расширение и прикрепляет `.xpi` к релизу.

1. В репозитории: **Settings → Secrets and variables → Actions → New repository secret**.
2. Создайте два секрета: `AMO_API_KEY` (JWT issuer) и `AMO_API_SECRET` (JWT secret).
3. Дальше достаточно поднять версию, закоммитить и выполнить `git tag vX.Y.Z && git push origin vX.Y.Z`.

Тег должен совпадать с версией в манифесте (`v2.0.0` ↔ `2.0.0`), иначе сборка остановится.

## 4. Обновления

- **Из каталога AMO** Firefox обновляет расширение сам.
- **Из GitHub Releases** самообновления нет, пока в манифесте нет `update_url`. Простой путь: в каждом релизе пишите, что нужно скачать новый `.xpi`. Автообновление возможно через `browser_specific_settings.gecko.update_url` на JSON-файл по HTTPS (формат: https://extensionworkshop.com/documentation/manage/updating-your-extension/).

## 5. Переход со старой версии

Идентификатор расширения сменился, поэтому новая версия не видит данные старой. Перед переходом:

1. В старой версии: меню «⋯» → **Экспорт / импорт данных** → **Скачать файл**.
2. Удалите старое расширение, установите новое (иначе два расширения будут бороться за новую вкладку).
3. В новом: **Экспорт / импорт данных** → **Загрузить файл**. Старые названия настроек переносятся автоматически, виджеты-аддоны не импортируются.

Плитки восстановятся из закладок и из папки «Табло» в закладках.
